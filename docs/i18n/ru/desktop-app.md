# Настольное приложение macOS: эксплуатация, безопасность и восстановление сопряжения

Последняя проверка: **11 ноября 2026 г.**

Приложение Tauri повторно использует существующий интерфейс Vue. Оно запускает встроенный daemon Gloamy, только если локальный работающий daemon не найден. К уже работающему daemon приложение подключается без присвоения себе права управления. WebView подключается только к `127.0.0.1` или `::1`; привязка к конкретному нелокальному адресу в этой версии POC не поддерживается.

В нативном меню указано **Gloamy Desktop v0.1.1**. Соседний пункт показывает версию gateway из частного управляющего сокета; для старых daemon без этого поля отображается «Не сообщается».

## Жизненный цикл daemon

Настройка «Оставлять daemon работающим после закрытия» хранится в параметрах приложения и по умолчанию выключена. В выключенном состоянии приложение запрашивает штатное завершение только у daemon с отметкой о запуске настольным приложением. Во включенном состоянии такой daemon продолжает обслуживать веб-интерфейс. При закрытии приложение никогда не останавливает daemon без этой отметки, включая старый daemon, обнаруженный через HTTP API.

## Восстановление сопряжения

На экране аутентификации или настроек запросите новый одноразовый код и завершите сопряжение через существующий `/pair`. Код передаётся по Unix-сокету управления, доступному только текущему пользователю, хранится в памяти и не записывается в конфигурацию или журналы. Новое сопряжение добавляет хеш токена и не отзывает существующие устройства. Если сопряжение отключено, запрос кода отклоняется. HTTP-метода генерации кода нет.

## Локальное управление и безопасность

Сокет расположен по пути `$TMPDIR/gloamy-<uid>/control.sock` (или в эквивалентном временном каталоге системы). Права каталога — `0700`, сокета — `0600`. Протокол поддерживает только получение статуса, запрос кода сопряжения и штатное завершение. Выполнение произвольных shell-команд и запись конфигурации недоступны. Сокет защищает от других локальных пользователей, но не от процессов с тем же UID. Существующая проверка bearer token в daemon сохраняется.

## Устранение неполадок

- **Адрес занят:** остановите службу, использующую заданные host и port, либо измените `gateway.host` / `gateway.port` в `~/.gloamy/config.toml`. Приложение не запускает второй daemon.
- **Восстановление сопряжения недоступно:** проверьте, что сопряжение включено, и запросите код в настольном приложении. Браузер не может обратиться к локальному сокету управления.
- **Не удаётся подключиться к существующему daemon:** проверьте его доступность по настроенному loopback-адресу. Неуправляемый daemon продолжит работу после закрытия приложения.

Полные сведения приведены в [контракте безопасности управляющего сокета backend](https://github.com/averyfreeman/gloamy-app-server-oauth2/blob/main/docs/security/desktop-control-socket.md).
