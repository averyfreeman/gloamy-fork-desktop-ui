# macOS デスクトップアプリ: 運用・セキュリティ・ペアリング復旧

最終確認: **2026年11月11日**。

Tauri デスクトップアプリは既存の Vue UI を再利用します。正常なローカル daemon がない場合に限り、アプリ同梱の Gloamy daemon を起動します。正常な daemon がすでに動作している場合は所有権を取得せず接続します。WebView が接続するのは `127.0.0.1` または `::1` です。この POC では特定の非ループバックアドレスへの bind はサポートしません。

ネイティブメニューには **Gloamy Desktop v0.1.1** と表示されます。隣の項目にはプライベート制御ソケット経由で取得した gateway バージョンが表示され、バージョンを返さない旧 daemon では「報告なし」と表示されます。

## daemon のライフサイクル

「アプリ終了後も daemon を実行」はデスクトップ設定に保存され、初期値はオフです。オフの場合、daemon がデスクトップ管理対象と報告した場合に限り、アプリ終了時に正常終了を要求します。オンの場合、その daemon はブラウザー UI 用に実行を続けます。デスクトップ管理マーカーのない daemon（正常な HTTP API に接続した旧バージョンを含む）は、アプリ終了時にも停止しません。

## ペアリングの復旧

認証または設定画面から新しい一回限りのコードを要求し、既存の `/pair` フローを使ってペアリングします。コードは同一ユーザー専用の Unix 制御ソケット経由で渡され、メモリ内にのみ保持されます。設定ファイルやログには保存されません。新しいペアリングは既存トークンを無効化せず、トークンハッシュを追加します。ペアリングが無効な場合はコードを要求できません。HTTP にはコード生成 API はありません。

## ローカル制御とセキュリティ

ソケットは `$TMPDIR/gloamy-<uid>/control.sock`（または OS の一時ディレクトリ）に配置されます。ディレクトリ権限は `0700`、ソケット権限は `0600` です。操作は状態確認、ペアリングコード要求、正常終了の3つだけで、汎用 shell コマンドや設定書き込みは提供しません。同一マシンの別ユーザーからは保護しますが、同じユーザーで動くプロセスに対する境界ではありません。daemon の既存 bearer token 検証は維持されます。

## トラブルシューティング

- **アドレスが使用中:** 設定された host と port を使うサービスを停止するか、`~/.gloamy/config.toml` の `gateway.host` / `gateway.port` を変更してください。デスクトップアプリは daemon を二重起動しません。
- **ペアリングを復旧できない:** ペアリングが有効か確認し、デスクトップアプリから操作してください。ブラウザーからローカル制御ソケットには接続できません。
- **既存 daemon に接続できない:** 設定されたループバックアドレスで正常に応答するか確認してください。未管理 daemon はアプリ終了後も動作します。

詳細は[バックエンドの制御ソケットセキュリティ契約](https://github.com/averyfreeman/gloamy-app-server-oauth2/blob/main/docs/security/desktop-control-socket.md)を参照してください。
